# TGEARN

Два независимых Telegram-бота для закрытой демонстрации: **магазин** и **скупка**. Обычные кнопки в Telegram, отдельные базы, запуск на Python без Docker и сторонних библиотек.

Магазин выдаёт синтетические товары `LAB_RAW_`. Скупщик принимает сам учебный токен, без номера заказа и без обращения к магазину. Все суммы условные. Настоящие API-ключи, E-pay и денежные выплаты не подключены.

## Запуск

Нужны Python **3.11 или новее**, доступ к Telegram и два бота, созданных через официальный **@BotFather** в Telegram.

1. Скачайте репозиторий через **Code → Download ZIP** и распакуйте. Скопируйте `.env.example` в `.env` рядом с `README.md`.
2. Вставьте токены двух Telegram-ботов в `STORE_BOT_TOKEN` и `BUYBACK_BOT_TOKEN`. Это токены от BotFather; API-ключи других сервисов сюда не нужны. Списки `STORE_TESTER_IDS` и `BUYBACK_TESTER_IDS` пока можно оставить пустыми.
3. На Windows откройте `start-store.bat` и `start-buyback.bat`. В Telegram отправьте каждому боту `/id`. Добавьте свой числовой ID в соответствующий список в `.env`, остановите оба окна через **Ctrl+C** и запустите снова. Теперь отправьте `/start`.

Если Windows скрывает расширения, проверьте, что файл называется именно `.env`, а не `.env.txt`. Токены не нужно отправлять в чат или размещать на GitHub.

Вместо файлов запуска можно открыть два терминала в папке проекта:

```sh
python -m tgearn store
```

```sh
python -m tgearn buyback
```

На macOS/Linux команда Python часто называется `python3`. Оба процесса работают, пока открыты их терминалы и включён компьютер.

Проверка настроек без подключения к Telegram:

```sh
python -m tgearn store --check
python -m tgearn buyback --check
```

`--check` проверяет заполнение настроек. Он не проверяет действительность токена в Telegram. Если список участников пуст, доступна только команда `/id`. Остальные действия закрыты. Несколько ID разделяются запятой; доступ к каждому боту настраивается отдельно.

## Проверить за пять минут

**Магазин:** каталог → учебный пакет → «К покупке» → «Тест: подтвердить оплату». Бот покажет выданный токен. Он также останется в «Моих заказах».

**Покупка с доплатой:** откройте баланс, создайте пополнение на 1 000 ₽ и подтвердите его тестовой кнопкой. Выберите пакет за 1 200 ₽. Бот покажет недостающие 200 ₽, объяснит минимум пополнения 1 000 ₽ и попросит подтвердить сумму. После покупки на учебном балансе останется 800 ₽.

**Скупка:** «Примеры и тесты» → «Добавить примеры в базу» → скопируйте один из показанных токенов и пришлите отдельным сообщением → подтвердите. Покупать что-либо в магазине для этого не требуется.

**Отказ проверки:** отправьте пример до заполнения базы или очистите базу примеров. Бот сообщит, что совпадения нет именно в его базе. Это не заключение о работоспособности API-ключа.

**Повтор:** нажмите старую кнопку оплаты или отправьте уже принятый токен. Второго начисления или второй выдачи не будет.

## Что умеет магазин

- 6 позиций в разделах «Текст», «Изображения», «Аудио», «Видео»; при первом запуске создаются 3 000 учебных товаров.
- Покупка с нулевым балансом, целиком с баланса и с доплатой.
- Резерв товара и части баланса на время незавершённого заказа.
- Минимальное пополнение в модели — 1 000 ₽. Если доплата меньше, бот отдельно показывает сумму и будущий остаток.
- Счета, баланс и история заказов. Для другой суммы пополнения: `/topup 1500`.
- Отмена и тестовая просрочка освобождают резерв. Событие оплаты после закрытия счёта помечается для разбора и не выдаёт товар.
- Повторный запуск сохраняет покупки и не возвращает проданные экземпляры на склад.

| Учебный пакет | Цена в магазине | Цена в скупке |
| --- | ---: | ---: |
| Пакет $50 | 1 200 ₽ | 1 800 ₽ |
| Пакет $100 | 2 000 ₽ | 3 000 ₽ |
| Текстовый пакет $30 | 1 000 ₽ | — |
| Изображения $50 | 1 300 ₽ | — |
| Аудио $50 | 1 500 ₽ | — |
| Видео $80 | 1 900 ₽ | — |

Долларовые номиналы в таблице — обозначения примеров, а не реальные кредиты или подписки. Обещания о промоакциях и гарантиях поставщика в демонстрацию не включены.

## Что умеет скупка

- Своя изначально пустая база: она не читает заказы, баланс или базу магазина.
- Получение самого учебного токена. Регистр символов важен; пробелы по краям убираются.
- Отдельные результаты: неверный формат, нет совпадения, проверка приостановлена, пример уже принят, совпадение найдено.
- Подтверждение предложения в течение пяти минут с повторной проверкой базы.
- Один токен принимается один раз, включая попытку другого участника.
- Собственные условный баланс и история. Порог вывода в макете — 500 ₽; раздел прямо сообщает, что выплат нет.

Раздел «Примеры и тесты» доступен каждому допущенному участнику. Его кнопки меняют общую тестовую базу скупки для всех участников. Очистка примеров сохраняет принятые заявки и защиту от повторного начисления.

Для проверки используются только три встроенных синтетических образца. Один совпадает с первым примером A50 из магазина, два других существуют независимо. Этот набор задан в коде скупщика; он не импортируется из магазина. Приём реальных ключей и загрузка реестра настоящих товаров не реализованы.

## Если что-то пошло не так

| Ситуация | Что сделать |
| --- | --- |
| Бот показывает «закрытая демонстрация» | Получите `/id`, добавьте ID в нужный список `.env` и перезапустите этот бот. |
| Telegram не принял токен | Проверьте токен нужного бота в `.env`. `--check` не проверяет его через сеть. |
| Этот бот уже запущен | Закройте прежний процесс. Для одного бота нужен один работающий экземпляр. |
| Сообщение о webhook | Для этого бота уже настроена доставка сообщений в другой сервис. Проект не удаляет её автоматически; используйте отдельного нового бота или отключите прежнюю настройку там, где её включали. |
| Нет связи с Telegram | Процесс повторит запрос с паузой. Проверьте интернет; не запускайте дополнительные копии. |
| После кнопки не пришёл ответ | Откройте «Мои заказы», «Счета» или «Мои заявки». Сохранённая операция могла завершиться до ошибки отправки. |
| Остался незавершённый счёт | Откройте «Счета» и подтвердите, отмените или задайте тестовую просрочку. |
| У скупщика нет совпадения | Откройте «Примеры и тесты», добавьте примеры и пришлите один из них. |

Просрочка в этой демонстрации задаётся кнопкой; фонового таймера счёта нет. Платёжный провайдер не опрашивается. Пометка «требуется разбор» показывает итог теста поздней оплаты; рабочего процесса денежных возвратов нет.

## Данные и устройство

По умолчанию магазин хранится в `.data/store.sqlite3`, скупка — в `.data/buyback.sqlite3`. Общего баланса и связи по номеру заказа нет. Доступны разные токены ботов и разные списки участников. Попытка настроить одинаковый файл базы или один Telegram-токен для двух ботов отклоняется.

Операции проходят внутри транзакций SQLite. Повторные нажатия имеют сохранённый идентификатор действия; принятый токен защищён уникальным ограничением. Отдельная блокировка не позволяет двум процессам одновременно работать с одним файлом базы.

Боты получают сообщения через long polling по [официальному Telegram Bot API](https://core.telegram.org/bots/api). После обработки сохраняется номер следующего обновления. Ошибка доставки ответа не запускает действие ещё раз. При аварийной остановке между записью результата и номера обновления повтор защищён логикой самого действия.

Приложение не пишет входящие сообщения и секреты в журнал. Скупка хранит хеш и короткую маску принятого учебного токена. Само сообщение остаётся в чате Telegram: настоящие ключи присылать не следует.

`.env`, базы, файлы блокировки и локальные кэши исключены из Git. Для резервной копии остановите оба процесса и сохраните `.data` отдельно от публичного репозитория. Удаление базы удалит её историю и состояние.

| Файл | Назначение |
| --- | --- |
| `tgearn/store.py` | Каталог, склад, учебные счета и заказы |
| `tgearn/buyback.py` | Независимая база скупки и заявки |
| `tgearn/bots.py` | Кнопки и тексты Telegram |
| `tgearn/runtime.py` | Получение сообщений и восстановление соединения |
| `tgearn/config.py` | Настройки из `.env` и списка участников |
| `tgearn/telegram_api.py` | Узкий HTTPS-клиент Telegram |
| `tests/` | Проверки логики, доступа и сбоев |

## Проверки

```sh
python -m unittest discover -s tests -v
```

Тесты используют временные базы и подставной Telegram-клиент. Проверяются покупки, остатки, отмены, повторы, конкурирующие операции, перезапуски, доступ к чужим данным и ошибки отправки.

Исходники и сценарии проверены локально на Python 3.12/Linux. Живой запуск в Telegram, Windows-файлы запуска и реальные платёжные операции не проверялись. Проект предназначен для закрытой демонстрации; внешних платежей и выплат в коде нет.
